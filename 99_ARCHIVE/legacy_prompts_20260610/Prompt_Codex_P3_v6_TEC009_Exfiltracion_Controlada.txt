4. DEFINICIÓN METODOLÓGICA CORRECTA DE TEC-009
============================================================

TEC-009 debe interpretarse como:

“staging, archivado y exfiltración HTTP controlada de datos dummy en laboratorio”.

Matiz obligatorio:

- Sí hay transferencia efectiva de datos.
- Sí hay exfiltración controlada de un ZIP dummy.
- No hay exfiltración de datos sensibles reales.
- No hay credenciales reales.
- No hay datos corporativos.
- No hay terceros comprometidos.
- El receptor HTTP pertenece al investigador.
- La prueba es válida para evaluar detección host-based de comportamiento compatible con exfiltración.

Formulación académica correcta:

“TEC-009 reproduce una cadena controlada de staging, archivado y exfiltración HTTP de datos dummy en laboratorio. El archivo ZIP generado en la VM es transferido mediante HTTP POST hacia un receptor propio del investigador, registrándose HTTP 200, bytes recibidos y hash SHA256. Por tanto, la técnica permite evaluar detección de exfiltración a nivel host-based sin utilizar datos sensibles reales.”

No escribir:

- “exfiltración real de datos sensibles”.
- “robo de datos”.
- “compromiso real”.
- “exfiltración a un atacante”.

Sí escribir:

- “exfiltración HTTP controlada de datos dummy”.
- “transferencia efectiva del ZIP dummy”.
- “receptor HTTP propio del laboratorio”.
- “evidencia externa de recepción mediante receiver_log”.

13. FALSOS POSITIVOS Y FALSOS NEGATIVOS
============================================================

Riesgos de falso positivo:

- Scripts administrativos que usen Invoke-WebRequest + InFile.
- Subida legítima de logs/paquetes ZIP.
- Automatizaciones internas de backup.
- Despliegues DevOps.
- Herramientas de administración que transfieran archivos por HTTP.

Mitigación:

- Exigir combinación de señales:
  - staging/archive + upload;
  - ZIP + POST + InFile;
  - PowerShell + HTTP + archivo;
  - hash + upload;
  - Sysmon network como apoyo, no único criterio fuerte.
- No alertar por Invoke-WebRequest aislado.
- No alertar por .zip aislado.
- No alertar por conexión de red aislada salvo como Confidence Medium/contextual.
- No usar rutas de laboratorio como reducción de FP.

Riesgos de falso negativo:

- Upload con .NET WebClient.
- Upload con curl.exe real.
- Upload con certutil/bitsadmin.
- Upload con HTTPS sin command line visible.
- Script ofuscado.
- 4104 no habilitado o truncado.
- Sysmon sin ID 3/11/22 configurados.
- Uso de otro Content-Type.
- Uso de PUT en vez de POST.

Mitigación:

- Mantener 4104 + Sysmon ID1 + Sysmon ID3.
- No exigir puerto concreto.
- No exigir DNS.
- No exigir destino público.
- No exigir Sysmon ID11.
- Diseñar regex flexibles para Invoke-WebRequest/iwr/POST/InFile/application/zip/http/upload.
