# session_20260617_2027

## Resumen

Revision y correccion del router SOC porque `SOC_v2` funcionaba parcialmente:

- `soc_alerts.jsonl` mostraba solo `P1_CRITICAL`.
- P2/P3/P4 tenian filas en GUI, pero no llegaban al JSONL.

## Diagnostico

Causa principal:

- `SOC_v2` usaba una unica source con muchos `watch_monitoring()` dentro de `chain()`.
- En `SERVER_EVENT`, `watch_monitoring()` es una fuente viva/continua; una rama activa puede impedir que se alcancen ramas posteriores.
- Esto encaja con el resultado observado: solo se enrutaba la primera familia activa (`P1_CRITICAL`).

Causa adicional:

- `SOC_v2` apuntaba a P2 legacy `Custom.TFM.HIDS.P2.High.Forensic_v1`.
- El despliegue actual usa `Custom.TFM.HIDS.P2.High.Forensic.Event_v1` con 5 sources `Forensic_EVENT_*`.
